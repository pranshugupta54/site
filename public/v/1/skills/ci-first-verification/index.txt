24:T1532,<h1>CI-First Verification — Don't Kill the Laptop</h1>
<h2>The situation</h2>
<p>You are one of several agents working concurrently on this machine. Every full build, test suite, typecheck, or repo-wide lint you launch competes for the same CPU, memory, and disk as every other agent's work. A handful of agents each "just running the tests" brings the whole machine to its knees — and most of those runs duplicate verification that CI already does for free on the PR.</p>
<h2>The core rule</h2>
<blockquote>
<p>Before launching any heavy local process, ask: <strong>is CI already answering this question?</strong> If the branch has a PR, the answer is usually yes. Read the CI result instead of recomputing it locally.</p>
</blockquote>
<h2>Check CI instead</h2>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-dimmed"><code data-language="bash" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span style="color:#F69D50">gh</span><span style="color:#96D0FF"> pr</span><span style="color:#96D0FF"> checks</span><span style="color:#F47067"> &#x3C;</span><span style="color:#96D0FF">numbe</span><span style="color:#ADBAC7">r</span><span style="color:#F47067">></span><span style="color:#768390">            # pass/fail summary of all checks on the PR</span></span>
<span data-line=""><span style="color:#F69D50">gh</span><span style="color:#96D0FF"> pr</span><span style="color:#96D0FF"> checks</span><span style="color:#F47067"> &#x3C;</span><span style="color:#96D0FF">numbe</span><span style="color:#ADBAC7">r</span><span style="color:#F47067">></span><span style="color:#6CB6FF"> --watch</span><span style="color:#768390">    # only when you must block on a result</span></span>
<span data-line=""><span style="color:#F69D50">gh</span><span style="color:#96D0FF"> run</span><span style="color:#96D0FF"> list</span><span style="color:#6CB6FF"> --branch</span><span style="color:#F47067"> &#x3C;</span><span style="color:#96D0FF">branc</span><span style="color:#ADBAC7">h</span><span style="color:#F47067">></span><span style="color:#768390">    # workflow runs for the branch</span></span>

<p>Typical loop: push → <code>gh pr checks</code> → read failures from logs → fix → push → let CI re-verify. No local build ever ran.</p>
<h2>No PR yet?</h2>
<p>If the branch has no PR (<code>gh pr view</code> fails), don't silently fall back to heavy local runs — <strong>ask the user</strong> which they prefer:</p>
<ol>
<li><strong>Create a PR now</strong> (draft is fine: <code>gh pr create --draft</code>) so CI takes over verification, or</li>
<li><strong>Run the checks locally</strong> this once, scoped as narrowly as possible.</li>
</ol>
<p>Default recommendation to the user: the draft PR — it costs nothing, CI does the work, and every later verification in the session is free. Only skip the question and go local when the repo has no CI configured at all (no <code>.github/workflows/</code>), or the user already told you which way to go.</p>
<h2>Heavy processes — avoid by default</h2>
<ul>
<li>Full project build (<code>npm run build</code>, <code>cargo build</code>, <code>tsc</code> over the project, bundlers)</li>
<li>Whole test suite (<code>npm test</code>, <code>pytest</code>, <code>go test ./...</code>)</li>
<li>Repo-wide lint or typecheck</li>
<li>Dev servers / watch mode left running after you're done</li>
<li>Dependency installs when node_modules already exists and the lockfile didn't change</li>
</ul>
<p>Run one of these locally only when ALL of: (1) no CI covers the question, (2) the answer blocks your next step, (3) you scope it as narrowly as possible. Say in your response that you ran it and why.</p>
<h2>Cheap local alternatives (fine to use)</h2>
<ul>
<li><strong>Single test file</strong>, not the suite: <code>npx jest path/to/one.test.ts</code>, <code>pytest tests/test_one.py -k case</code></li>
<li><strong>Targeted lint</strong>: <code>npx eslint &#x3C;changed files></code> — never <code>.</code></li>
<li><strong>Syntax check one file</strong>: <code>node --check</code>, <code>python -m py_compile</code>, editor/LSP diagnostics</li>
<li><strong>Reading code</strong> — cheapest verification there is; often you can confirm correctness by tracing the change instead of executing anything</li>
</ul>
<h2>Multi-agent etiquette</h2>
<ul>
<li>Never run heavy processes "proactively" or "to be safe" — only when the result is needed and CI can't provide it.</li>
<li>One process at a time: don't parallelize builds with tests locally.</li>
<li>Kill what you start: no orphaned watchers, servers, or daemons when your task ends.</li>
<li>If another agent's build is likely running (system feels loaded), prefer CI even harder.</li>
</ul>
<h2>Litmus test</h2>
<p>Before any command that will spin fans: <strong>"Will the PR's checks tell me this within a few minutes anyway?"</strong> If yes, read the checks.
